## Open obligations

- **AC-OB-001** — Raw Git commands can bypass the broker. Deployments that
  require hard enforcement still need protected branches, required review, or
  an authoritative remote merge queue.
- **AC-OB-002** — The Hub's direct-TLS or loopback-proxy boundary and hashed,
  revocable device enrollment are implemented and tested for the V1 topology.
  V1 still trusts every enrolled PC and supports one owner only: it has no
  users, teams, tenants, RBAC, external identity provider, or horizontally
  available service. The production-workstation server stays loopback-only;
  exposing its path-discovery API remotely is never an acceptable substitute.
- **AC-OB-003** — A shared `.agentconduit/project.json` `projectId` creates a
  coordination namespace across independent clones; it is not an authoritative
  remote-ref lock. Safe cross-clone integration needs one authoritative clone or
  a repository-approved remote synchronization/merge queue.
- **AC-OB-004** — There is no administrative force-complete transition for an
  orphaned or uncertain external Git operation. Preserve the claim, inspect the
  broker and Git states, and reconcile with an operator.
- **AC-OB-005** — Provider-native push is version-sensitive and only verified
  for runtimes explicitly owned by a bridge process. It is not a guarantee for
  arbitrary interactive/Desktop sessions; Codex app-server elicitation and
  steering methods are likewise version-sensitive. Keep durable inbox polling
  as the portable correctness path.
- **AC-OB-006** — Abandoned bridge registrations remain visible as `stale`
  until their own heartbeat timeout and are not automatically reaped. A new
  bridge must use a new session identity unless it has the prior session token;
  cleanup/reconciliation must inspect broker and real runtime state before
  touching any lease or integration claim. If a bridge-owned process is still
  alive and heartbeating, a chat-UI switch alone cannot prove abandonment;
  the owner must send an explicit stop/runtime-exit signal.
- **AC-OB-007** — Production POSIX ownership and mode checks are implemented,
  but equivalent Windows ACL enforcement is not. Windows operation remains an
  explicit unverified limitation until owner/private-directory and token/database
  access are implemented and tested with native ACL evidence.
- **AC-OB-008** — `pnpm ci:check` structurally validates immutable action,
  reusable-workflow, local-action, container, local Dockerfile, and local
  JavaScript entrypoint dependencies, but it runs only after checkout and tool
  bootstrap. A hosted repository still needs externally enforced full-SHA
  action policy or protected workflow review as a required merge gate.
- **AC-OB-009** — Git discovery uses bounded synchronous child processes. Each
  command has timeout and output caps, but a slow allowed repository can pause
  the Node event loop during that bound. The single-user workstation topology
  accepts this as an operational limit; multi-client availability needs an
  asynchronous bounded worker/queue.
- **AC-OB-010** — The owner selected `aididhaiqal/AgentConduit` as the public
  source repository and MIT as its license. Package-scope ownership, signing,
  provenance, and publication remain separate owner decisions and are not
  configured. Successful local package smoke tests do not authorize or
  establish a published supply-chain identity.
- **AC-OB-011** — The packaged workstation and multi-PC production profiles
  have not been installed, restarted, backed up, restored, upgraded, enrolled,
  or runtime-verified on operator PCs. Those external-state checks require an
  explicitly authorized target and remain distinct from source/test/package
  completion.
- **AC-OB-012** — Dashboard static, responsive, keyboard, and accessibility
  contracts have automated coverage, but desktop and narrow-layout screenshot
  critique was not completed because the available computer-use session stayed
  attached to Atlas. Manual visual and operator-browser verification remain due
  before claiming dashboard runtime verification.
